# Day 2 submission checklist

- Rehearse FINAL_DEMO_SCRIPT.md once with fresh mock records; keep V1 default and network-dependent inference out of the scripted walkthrough.
- Presentation: problem, architecture, human safeguards, two scenarios, measured trade-offs, limitations. Use FINAL_COMPETITION_CLAIMS.md; no V2 superiority, production-readiness or independent-accuracy claims.
- Video: record a 7-9 minute walkthrough; show MOCK/DEMO labels continuously for scripted output. Any live benchmark screenshot must be identified as historical cached results. Include photograph attribution/license information; never record credentials or sensitive local paths.
- README: link final startup scripts, tested ports, acceptance report and dated completed evaluation reports. Clearly distinguish older pending-run reports; retain originals.
- Submission package: include source, dependency lockfiles, permitted fixtures with attribution, documentation and sanitized evidence. Exclude .env, API keys, .venv, node_modules, .next, personal uploads, private databases, browser traces containing private data and local-only absolute-path manifests unless sanitized.
- Security: inspect package/built assets for secrets; use blank .env.example; keep loopback binding. Demo role is not authentication. Do not expose the app publicly.
- Confirm original/historical datasets, prompts, source licenses and report hashes are retained. No last-minute label or scoring changes.
- Verify package startup from documented commands; keep a local backup and mock fallback PRESENTATION plan that is explicitly labeled, never a silent real-provider fallback.
- Final submit: check competition file limits/naming, links and permissions; approve actual submission separately. No deck/video or external submission was created in Day 1.
